# Roo v1.4.2 更新说明

## 新增：前置代理单独探测 + 故障归因

住宅节点需要海外网络才能访问，经常前置代理挂了就连带一串节点异常，但面板上只能看到"N 个节点异常"，分不清是前置问题还是节点问题。

v1.4.2 把前置代理的健康度**独立提出来**探测并标注：

### 面板变化

**CONSOLE · NET DIAGNOSTICS · 当前路径**：前置代理块多了健康徽章

```
┌── 前置代理 ──────────────── [● 正常] ─┐
│ socks5://127.0.0.1:6578               │
│ 前置出口：43.239.95.22 · SG · 180 ms  │
└──────────────────────────────────────┘
```

异常时：

```
┌── 前置代理 ──────────────── [● 异常] ─┐
│ socks5://127.0.0.1:6578               │
│ 探测失败：curl: (7) Failed to connect │
└──────────────────────────────────────┘
```

**出口检查** 异常节点条目上：

```
[美国-纽约]  [疑似前置拖累]             [● 异常]
环境代理链路探测失败：curl: (56)…
```

**顶部 status-strip**：前置挂了时直接显示"前置异常"头条，而不是"出口节点异常"——避免错归因。

### 顶部 routeHint 优先级

```
1. 前置代理自身失败 + 节点失败 → 明确提示归因到前置
2. 前置代理自身失败（无节点失败） → 提示前置会拖累所有依赖它的节点
3. 只有节点失败 → 按原逻辑提示排查节点
4. 正常状态 → 照旧
```

### 技术实现

- **`dashboard/index.js` getNetworkDiagnostics**：新增 `probeRelayProxy()`——用 curl 走 env proxy 打 api.ip.sb，拿 IP + 延迟 + 错误
- 返回 `relayProbe: { configured, ok, ip, meta, error, latencyMs }`
- `buildNetDiagSummary` + `renderNetDiag`：前置异常优先级最高；节点异常时若节点走 via-chain / env-proxy 模式，自动打上"疑似前置拖累"徽章
